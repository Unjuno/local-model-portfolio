# R71｜v32有効135資産と歴史的取得候補15マニフェストの再利用可能証拠索引（2026-11-15）

## 1.〈本論〉

正本は`catalog/CURRENT.json` v32、登録182/有効135（SELECT53、CONDITIONAL82）。[R71の全135件機械可読索引](../../catalog/research/2026-11-15-r71-v32-135-cross-draft-source-index.json)は、`manifests/drafts/*.candidate.json`にある15ファイルを全数読み、**asset repo IDの完全一致**で結合。版・形式・外部部品は分け、モデルの独立学習済み状態として自動採用しない。

### 証拠の意味

1. たとえば`qvac/BotPsy-0.8B`はR49とR64の両方に現れる。**同じ資産が2件増えたわけではない**。出典を2本保存し、SHAやrevisionの整合性を見られるようにした。
2. `mistralai/Mistral-Small-4-119B-2603`等の複数形式は、同じ原本の別backend表現として扱い、単純合計容量や独立学習済み資産件数に加算しない。形式間の同値性も別途検証する。
3. LoRAと親モデル、音声TTSのCodec、動画モデルのtext encoder/VAEは別依存repoとして台帳に存在し得るが、有効資産の分母には加えない。**保存の完全性の判定には親repoの権利・ABI・SHAまで必要**。
4. source SHAがあるだけでは配布元の最新版ではないかもしれない。immutable revisionと同一ファイル・同一byteの組を保持する。
5. R70で`nvidia/RFD4-Proteina`について旧観測revとR64固定revの**root SHA一致・旧release manifestだけ不整合**を確認済み。元のR69履歴的照合（revision文字列不一致）を消さず、R70で具体的な重み同一性を補足する。

### R64との関係

既存の[R64全135資産レディネス台帳](../../catalog/readiness/v32-2026-11-15-r64-all-active.json)は126件を「v27歴史的source census」、その他9件を新規source evidenceとして分ける。この126件はモデルファイルについて**最近の最終ロック・現物SHAを全数再検証したものではない**。R71はその履歴証拠を再利用する追加のcross-referenceであり、代替・追認ではない。

## 2.〈応用・転用例〉

次回は「存在する資料をもう一度調べる」のではなく、R71の各行に記録された`draft_candidate_source_evidence`を起点に、選定ファイルscope・rev・SHA・利用許諾・外部依存・実HDDハッシュを検証する。最初のオフライン復元pilotは小さく依存の少ない`ibm-granite/granite-timeseries-ttm-r3`を優先してよいが、**ユーザーの合法的な所有と明示承認がない限り実ファイル取得・起動はしない**。
