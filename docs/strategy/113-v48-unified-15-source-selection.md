# R113 — v48統合取得候補15原本を単一の固定sourceに整理（2026-11-19）

## 1. 〈本論〉目的と今回の確定

現行正本v48は201登録・154有効（SELECT53／CONDITIONAL101）。旧v47の14モデルのpublisher固定ファイルと、新規v48のn4ze3m/tiny-vocaのFP32原本14ファイルを、**1つの非実行・未承認取得候補リスト**に統合した。

[統合15原本・187ファイルのmachine-readable source queue](../../queues/proposed-v48-r113-source-pinned-15.json)。旧14モデルのsource revision・ファイル・SHAを変更しない。追加はtiny-vocaの独立FP32学習済み重みとphonemizer辞書のみ。ONNX/GGUF各量子化を別資産として重複保存しない。

## 2. 確定対象の優先順位

最小の実保存パイロットはIBM TTM R3（5,748,963 byte）。次にtiny-voca（23,626,858 byte）、LingBot Touch Tiny（21,873,479 byte）、Nemotron diarization（397,030,277 byte）、Kitten TTS 2 Mini（477,936,075 byte）、Galvanize-3（597,001,839 byte）、BotPsy（1,726,201,481 byte）、ARLoop（4,838,079,760 byte）を独立学習成果として優先。

無検閲は**0bserverx RVN-Q4 multilingual（17,176,692,278 byte）とInterpretic selective political edit Q4（17,738,327,225 byte）**を異なる後学習済み成果として保存する。通常のQ5/Q6/Q8の同族量子化は追加しない。DSpine draft（4,051,857,976 byte）は親の正確なQwen3.8 27B sourceとの互換性確認が必要。

大型Gryphe/PantheonとDavidAUは保全研究を継続するが、両者合計108.711GBを即時取得対象には昇格しない。OrcaRouterはGatedであり、許諾を推定しない。画像LoRAは独立した後学習アダプターだが、親と非商用条件を満たすまで完全復元不能。

## 3. 実行ゲートと事実・予測

事実：Hugging Face公式メタデータによりARLoop、Kitten、tiny-voca、Galvanize、TTM、RVN、Interpreticの配布状況・ライセンスタグを再確認。モデル固有の将来の配布停止確率は**推定できない**。政策規制の拡大はシナリオであって現在の一律所持禁止を意味しない。Exaはクレジット上限HTTP 402で今回の新規検索結果を得られなかった。

取得GOは実HDDの空き200GBを維持できること、Gated本人許諾、利用行為に対応した原文LICENSE/NOTICE、全必須親・codec・ABI・コードの固定、ローカルSHA256の確認、明示的取得承認が必要。既存の接続Linux約50.88GBは4TBアーカイブではなく、空き約29GBで政策上の容量FAIL。新しいキューは**実行用ではない**。

## 5. H/T/D/C/U・ERROR CHECK

- H：元14原本を変更せずtiny-vocaの独立FP32原本だけを追加することで、重複量子化を増やさずに小型音声生成方式を保全できる。
- T：15 ID・187ファイル・74 publisher SHA参照を元v47 14原本とv48 1原本の入力から再集計、重複ID・容量・SHA整合性で逐次停止。
- D：source計数と選択スコープ一致＝PASS_METADATA。実4TB・本人権利・最終ハッシュ・offline restore＝UNCERTAIN。無許可のGated取得・実容量超過はFAIL。
- C：tiny-vocaのphonemizer依存が再現できない、元モデルの権利が制限される、同一学習済み重みの量子化を誤って別原本扱いする場合。
- U：publisher sourceサイズは最終ディスク使用量ではなく、実環境のキャッシュ/親重み・ABI未計測。校正データがないため合成標準不確かさu_cと係数kは推定しない。
