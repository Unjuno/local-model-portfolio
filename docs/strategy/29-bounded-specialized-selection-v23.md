# 29 — 116件のファイル容量確認後、独立学習成果2件を条件付き選定（v23・2026-11-06）

## 判断

最上位目的は、公開重みが将来消失した場合でも独立した学習成果を失わないこと。何を保存するかは固有の後学習重み・再現困難性で決め、能力別の先行配布制限は**取得準備の順序**とする。規制される確率は発表資料から求められず捏造しない。今回の選定はv22の116件の配布元一次ファイル範囲が算定された後の**2件だけ**である。既存163件の採否は一切変えず、実ファイル取得・クラウド課金・モデル実行はしない。

## 元の選定容量と未完了の区別

v22配布元メタデータの範囲は116/116件、一次ファイル総和3,110,000,142,272 byte、論理重複排除後3,108,440,834,201 byte。Granary-v2の148ラベル全件・LICENSE分割を反映済み。ただし完全オフライン復元の外部依存未解決25件、利用者の保存先実空き・既存ローカルハッシュ未計測。**v23の追加2件を加えた118件全体の最終総容量が確定したわけではない。**

固定版の配布元**全リポジトリ**容量：Holotron4が66,051,239,820 byte、DSparkが656,291,264 byte、合計66,707,531,084 byte。これは選んだ必要ファイルの最終容量、実行時メモリ、ディスク占有量ではない。既知のv22論理容量に全repoをそのまま追加する保守的な計画シナリオは3,175,148,365,285 byte。4TBとの差額824,851,634,715 byteは**実空きではない**。選定計画枠は70GB＋1GB＝71GBで、外部依存と現物計測が完了するまでダウンロードを承認しない。

- **保存価値：** 元のNemotronH Nano Omniから専用のGUI・MCP・コード操作に後学習した独立系列のMoE。既存Holo4-27BのQwen系学習成果と同一重みではない。17分割のBF16 safetensors重みとNemotron系の独自処理・トークナイザー・chat template、元の利用条件とsource versionを1組に保全する。
- **容量と総数：** Hugging Faceの固定版`52184310f6c916e5e7d4b8f055af49fc41642574`の全repo 66,051,239,820 byte。HF Safetensors属性は33,015,598,915スカラー（BF16 33,015,595,968、F32 2,944、I64 3）で、3Bの活性MoEを総パラメータと誤認しない。この数字は全シリアライズ要素のスクリーニング上限であり、外部学習済み依存の完全総数ではない。
- **肯定的証拠：** [作者モデルカード](https://huggingface.co/Hcompany/Holotron4-30B-A3B)で、元基盤と比べOSWorld21.0→76.3、AutomationBench19.4→35.6、PinchBench84.7→88.6と記載。作者による別後学習の証拠だが独立実験ではない。

- **制限区分：** 現在は公開repo表示。具体的な削除予告・政府命令は未確認。GUI操作・外部実行モデルに先行制限が及ぶ可能性は仮説で、S1で準備する。

## 保全と検証の最小条件

両者とも`conditional`（長期保険の選定）に加える一方、実ファイルの選別とSHA・license・依存部品の完全確認、必要な実機容量、ダウンロード明示承認は未実施。これらを補足せずに`download_enabled`や`queues/approved.json`を有効化しない。

### H/T/D/C/U

- **H（反証可能仮説）：** 2件は既存116件とは異なる後学習重み・ドラフターを保存し、原モデルだけでは再生できない。独自性・依存完全性・容量を固定版で検証する。
- **T：** まず原本のSHA、分割ファイル全数、利用条件、必要コード/target互換を静的監査。別承認で同一HW/clock/backend/context/batchの品質・速度試験を各30回以上。測定前に用途別閾値を登録する。
- **D：** PASS=独立学習成果と合法な必要部品を確認、4TB予算・200GB安全余白・実機RAM規則を全て充足。FAIL=同一重みの再パッケージ、著しい欠損、利用権不適合。UNCERTAIN=現段階は必須依存と現物容量未確認で取得不可。
- **C：** HolotronはHolo4との差が実験設計で消える、DSparkは元24Bの版・FP8と不整合、量子形式やruntimeの問題で復元不能。
- **U：** publisher source file bytesは整数として正確だが現物ハッシュとFS割当は未測定。未知の依存やclocks/batchの差が支配的。`u_c`・`k`の数値は誤差分布がないため求めない。

**ERROR CHECK：** 旧163件をそのまま保持して165件／有効118件、追加2件はダウンロード非承認、既存4TBと200GB床は変更しない。現在の実ディスク容量・利用者アクセス権・キャッシュ・実行速度・完全復元は未測定。機械学習の独自性、供給網でのSHA依存、法的利用条件、長期アーカイブの復元可能性を分けて扱う。
