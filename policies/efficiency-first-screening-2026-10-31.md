# 省容量・固有能力を重視する選定運用案（2026-10-31）

> 第7回までの調査を基にした**ドラフト方針**。現在の`policies/selection.md`を勝手に上書きするものではない。必須の適法性、3.8TB保存容量、HDD空き200GB、推論ピークRAM512GB未満を維持。

## 基準

**目的：** 法的に保持できる独自の能力・後学習原本・専門データについて、将来の再取得困難性と、保存一式の必要費用を両方重視する。最大モデルや最大パラメータ数を収集目標としない。

| 項目 | 最低条件 |
| --- | --- |
| 正規取得と権利 | 公式ID、現在のアクセス状態、対象重みの適用LICENSE、本人の利用許可を確認。未承認Gated/権利未解決は取得しない |
| 独立価値 | 既存重み・簡単な量子化・同じ系列の別checkpointとの差、独自訓練データ/追加学習/能力を一次資料に基づき具体化 |
| 保全リスク | Gated、公式配布変更、リポジトリの保守終了、原本の唯一性といった観測事実を区別。将来の政府規制確率を創作しない |
| 容量コスト | `full_repo`と`selected_files`を分け、完全revisionの各ファイル容量とTokenizer/Codec/Encoder/必要実行器・ランタイムの重複除去後の容量を記録 |
| 精度と速度 | 同一タスクかつ同一評価データ/分割で精度・失敗率・レイテンシ・ピークRAMを比較。HW/クロック/バッチ/量子化/バックエンドを固定するまで数値コスパ順位は保留 |
| 原本保存 | 操作用の軽量版と研究用の高精度原本を異なる用途として扱う。蒸留・4bit圧縮が高精度原本の損失を不可逆化する場合がある |
| 見送り基準 | 同等の学習済み能力が合法かつ容易に再入手できる／必要な依存が権利上不可能／同じ機能を低容量で実測した候補に一方的に劣るなら保留・後順位 |

## 今回の適用例

- 既存DINOv3 ViT7Bの全repo約26.864GBと、新たに選んだViT-Sの約86.4MBは大きく異なる。**しかし蒸留版は同一重みではなく、7Bを自動で外さない**。下流で同等のタスクを実測してから、実用比較版と研究用原本の保存要否を決める。
- SAM2 Tinyはリポジトリに旧`.pt`と`safetensors`が約156MBずつあるため、必要な形式だけを選ぶ。`.pt`の安全性と研究上の唯一性は別審査。
- SmolVLM2-500Mはモデルファイル約2.03GBに対し全repo約7.92GB。用途が許せば不要なONNX・代替形式を保存せず、完全オフラインで必要なProcessor等だけを選ぶ。
- OmniParserは一つのリポジトリ内にAGPL-3.0とMITのモデルを含む。**安さより先にファイル別の利用条件**を確認。現在mainとrefs/pr/37を固定して初めてMIT版の組合せを比較できる。

## 実装上の注意

重みファイルのデータ型、シャード、ABI、CPU/GPU backend、ドライバ、電力上限、コンテキスト、バッチ、KVキャッシュによりディスク容量と実際の性能は変わる。ソフトウェアのソースを列挙しただけではオフライン実行環境は完成しない。

比較を伴う判定にはH/T/D/C/Uを記録する。観測していない精度・速度・RAMはnullとして保持し、ベンダーの公称ベンチマークと独立検証を分ける。新規モデルのダウンロード、ソフトウェア実行、Gated同意は別の承認段階で行う。
