# Local Model Portfolio

**Offline AI Archive / Research Portfolio**

公開されているAIの重み・関連データ・実行環境を、将来もローカルで**利用・比較・解析・追加学習**できるよう保存するためのポートフォリオです。単なるモデルの人気ランキングやダウンロード一覧ではなく、再取得の難しさ、研究価値、アーキテクチャの多様性、再現可能性を考慮して収集対象を選びます。

> **現在の段階：選定基準の策定と候補の検証中。** GitHubにモデルの重み本体を置くプロジェクトではありません。候補を記載しただけでは、ダウンロード・動作確認済みを意味しません。

## 1. 保存目標と制約

| 項目 | 方針 |
| --- | --- |
| 保存媒体 | ローカルの4 TB外付けHDD（Windows 11 / NTFS） |
| 使用目標 | **3,800 GB（十進）** |
| 残す空き容量 | 原則 **約200 GB**（実測の空き容量に合わせて調整） |
| モデル規模 | **総パラメータ数250B以上を除外** |
| MoEの判定 | 推論時のactive parametersではなく、**全expertを含む総パラメータ数**で判定 |
| 優先する保存形式 | 解析・再学習に使える元の高精度重み（BF16 / FP16など）と、必要な実用量子化版 |
| 配布条件 | 正規にアクセスでき、ライセンスと利用条件を確認した資産のみ取得 |
| 実ファイル | HDD等に保存。Gitには台帳・手順・構成・検証結果のみ登録 |

GBは10^9バイト、GiBは2^30バイトです。リポジトリ単位の表示容量と実際に選択するファイルの合計は区別します。

| 分野 | 対象例・収集目的 |
| --- | --- |
| 言語モデル | Base / Instruct / Reasoning / Coding / 無検閲・abliterated派生。元モデルと改変後の比較を可能にする |
| アーキテクチャ | Dense Transformer、MoE、BERT系encoder、T5系encoder-decoder、SSM/Mamba、RWKV、拡散言語モデルなど |
| 画像・視覚 | 画像生成、画像編集、VLM、OCR、文書解析、セグメンテーション |
| 動画・世界理解 | 動画生成、動画理解、行動予測、world model、3D/空間モデル |
| 音声 | ASR、翻訳、TTS、音声対話、話者分離 |
| 特化モデル | Embedding / reranker、時系列、科学・生物・化学、その他代替困難なモデル |
| データセット | 事前学習、SFT、選好学習、評価データ。**評価セットは学習用データから隔離**する |
| オフライン知識 | 許諾された文献・技術資料・仕様・学習/評価レシピ |
| ソフトウェア | 推論エンジン、fine-tuningツール、トークナイザー、CUDA/ROCm等の依存環境、OS/ドライバー/インストーラー、コンテナ・隔離環境 |

## 3. 採用・優先順位の基準

各候補を次の軸で評価し、**採用 / 保留 / 除外**を記録します。

1. **再取得の不確実性：** Gated、配布条件、第三者派生、更新停止・公開状態の変化など。将来の削除や規制を根拠なく断定しません。
2. **再現困難性：** 元重み、学習データ、改変スクリプト、LoRA、学習手順の公開状況。再学習コストが大きいものを重視します。
3. **技術的独自性：** 既存アーカイブと異なるアーキテクチャ、用途、モダリティを増やせるか。
4. **研究可能性：** 高精度の重み・トークナイザー・構成・コード・評価条件を揃えられるか。**Baseとpost-trainedを混同しない**。
5. **実用性：** 手元または現実的に調達可能なハードウェアで動かせるか。必要VRAM/RAM、推論速度、互換性を調べます。
6. **容量効率：** 同一モデルの不要な量子化違い・重複ファイルを避け、空き容量と多様性の両方を維持できるか。

**容量を埋めることは目的ではありません。** 最終的には3,800 GBを目指しますが、未検証のデータや意味のない重複で埋めません。

## 4. 1モデルずつ行う検証

モデルの候補を追加するときは、最低限次を確認します。

- Hugging Face等の**配布元URL・正確なリポジトリID**と、公式/派生の区別
- 総パラメータ数、モデル種別、Base/Instruct等の学習段階
- 公開/Gated/非公開などの取得状況、**実際のライセンス本文**
- 保存対象の**ファイル名・バイト数**（必要な設定、tokenizer、processor、mmproj、LoRA等を含む）
- 特定の**commit SHA**、取得日時、ローカルのSHA-256
- 対応ランタイム、必要なメモリ、カスタムコード、依存ソフト
- 採用理由、比較対象、残る不確実性、独立評価の有無

**状態の定義**

| 状態 | 意味 |
| --- | --- |
| Candidate | 名前やURLを発見。存在・内容は未検証 |
| Reviewed | 一次資料で配布元・条件・容量等を調査 |
| Approved | 保存するファイルと容量を選定し、取得対象として承認 |
| Downloaded | HDDへの取得が終了 |
| Verified | ファイル数・サイズ・SHA-256等で整合性確認済み |
| Tested | 対応ランタイムで実際に読み込み・動作確認済み |
| Excluded | 250B以上、ライセンス不適合、重複、予算等の理由で除外 |

配布者の性能ベンチマークや「無検閲」の効果は**自己申告として記録**し、独立した測定と混同しません。

## 5. セキュリティとライセンス

- Gatedモデルは**正規の承認後**に取得します。アクセス制限は回避しません。
- 重みや関連コードの由来を確認します。未知のPythonコード、pickle/PT、カスタム処理系は信頼せず、可能な限り隔離・検査します。safetensors/GGUFも無条件に安全とは扱いません。
- GitHubは公開される可能性があるため、**トークン、認証情報、私的データ、外部配布が許可されないファイルをコミットしません**。
- ライセンスのメタデータだけで再配布可否を判断せず、元の契約・モデルカード・関連素材の条件を確認します。
- 保存と公開・再配布は別の行為として扱います。

## 6. リポジトリと実際のHDDの役割

**このGitリポジトリ：** 採用基準、候補台帳、出典、ファイルマニフェスト、検証方法、実行環境の再構築手順を管理します。

**ローカルのHDD：** モデル重み、データセット、ライセンス・ドキュメントのコピー、ソフトウェアアーカイブ、検証ログを保存します。

管理リポジトリ自体は軽量に保ち、HDDの接続先・ドライブ文字を固定値として仮定しません。ダウンロードや削除などの書き込み操作は、対象ディスクと保存先を確認してから行います。
